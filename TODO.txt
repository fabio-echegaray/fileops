--- FILE: fileops/scripts/_config_update.py ---

1. [BUG] check_duplicates() writes output to CWD with relative path (line 23)

   counts.to_excel(f"counts-{column}.xlsx")

   The output file is written relative to the current working directory,
   not to any logical project location. Users may not find the file, and
   the path is unpredictable if CWD changes during execution.

   Fix: Write to the same directory as the input summary file, e.g.:
     counts.to_excel(lst_path.parent / f"counts-{column}.xlsx")

---

2. [BUG] check_duplicates() only called in update_config_files(), not in
    update_from_cfg_folder() (lines 44, 50, 55)

   update_from_cfg_folder() never calls check_duplicates(), so duplicate
   entries in the summary file may go undetected until update_config_files()
   runs. This can lead to silent data corruption when merging config folders.

   Fix: Add check_duplicates() calls in update_from_cfg_folder() before
   the merge operation.

---

3. [BUG] check_duplicates() raises IndexError for business logic errors
    (line 25)

   raise IndexError(f"duplicates found in column {column} of the dataframe")

   Using IndexError for duplicate detection is semantically incorrect.
   Callers must catch IndexError which also catches legitimate index errors,
   making debugging harder.

   Fix: Create a custom DuplicateEntryError exception class.

---

4. [BUG] update() uses os.chdir() which affects global state (lines 95, 123)

   os.chdir(ini_path)
   ...
   os.chdir(cwd)

   Changing the working directory is not thread-safe and makes the function
   non-reentrant. If an exception occurs between chdir calls, CWD is never
   restored.

   Fix: Use Path objects with absolute paths, or wrap in a
   contextmanager that ensures CWD restoration.

---


--- FILE: fileops/scripts/summary.py ---

5. [BUG] update_from_cfg_folder() uses merge_column(use="x") which overwrites
    summary edits (line 278)

   for col in ["cfg_path", "cfg_folder"]:
       dfm = merge_column(dfm, col, use="x")

   This prefers config-side values, silently overwriting any intentional
   edits the user made to cfg_path or cfg_folder in the summary spreadsheet.

   Fix: Use merge_column(use="y") to preserve summary-side edits, or
   prompt the user for which side to prefer.

---

6. [BUG] update_from_cfg_folder() only updates "Files-Timeseries" sheet
    (lines 291-299)

   The method removes and replaces the "Files-Timeseries" sheet but does
   not update "Files-Stills". Still images with cfg_path/cfg_folder
   changes will not be reflected in the output.

   Fix: Apply the same merge logic to still images and write them to
   the "Files-Stills" sheet.

---

7. [BUG] merge_column() uses deprecated pd.options.mode.use_inf_as_na
    (lines 182-183)

   _inf_as_na_opt = pd.options.mode.use_inf_as_na
   pd.options.mode.use_inf_as_na = True

   This option was deprecated in pandas 1.x and removed in pandas 2.0.
   Running on pandas 2.0+ will raise AttributeError.

   Fix: Use pd.options.mode.use_inf_as_na with a version check, or
   replace with explicit NaN/inf handling via np.isinf().

---

8. [OPT] merge_column() mutates global pandas options (lines 182-189)

   Even with the current pandas version, temporarily changing a global
   option is not thread-safe and can affect other concurrent operations.

   Fix: Use a local copy or explicit value replacement instead of
   changing global options.

---


--- FILE: fileops/scripts/_utils.py ---

9. [BUG] _read_summary_list() doesn't handle missing "Channels" sheet
    gracefully (line 14)

   ch = pd.read_excel(path, sheet_name="Channels").fillna('')

   If the Excel file has no "Channels" sheet, this raises a KeyError.
   The .ods path has a try/except for this, but the .xlsx path does not.

   Fix: Wrap in try/except KeyError like the .ods branch:
     try:
         ch = pd.read_excel(path, sheet_name="Channels").fillna('')
     except KeyError:
         ch = None

--- Z-PROJECTION HANG — FILEOPS INTERNALS (moved from MovieRender TODO) ---

  [DONE] 40. Duplicate `s_lock`, missing `s_semaphore` in `fileops/__init__.py`
              — Line 13: `s_lock` declared twice, `s_semaphore` absent.
              Line 25+28: two Lock objects created, first is orphaned.
              Fix: rename second `s_lock` to `s_sem`, create one Lock only.

  [DONE] 41. `lock.release()` without matching `acquire()` (`_shared_zproj_state_mixin.py:167`)
              — In `z_projection()`, the `else` branch at line 166 releases
              `self._zcache_lock` without a prior `acquire()`. This corrupts
              the lock state, causing subsequent `lock.acquire()` calls in
              `_zproject()` (lines 195, 204, 249) to hang forever.
              Fix: remove the stray `release()` at line 167; the lock is
              not held in that branch.

  [DONE] 42. Slice assignment destroys `Manager().list()` proxy (`_shared_zproj_state_mixin.py:67`)
              — `self._zcache_priority = self._zcache_priority[20:]` replaces
              the managed list proxy with a plain Python list. After this,
              the z-project thread and main process hold different objects —
              priority items appended via the proxy are invisible to the thread.
              Also caused the z-project hang: `del self._zcache_priority[:20]`
              removed frames consumers needed from the priority queue.
              Fix: removed the entire `del self._zcache_priority[:20]` line.

  [OPEN] 43. `lock.acquire()` without timeout (`_shared_zproj_state_mixin.py:195,204,249`)
              — Three bare `acquire()` calls in `_zproject()` can hang forever
              if the lock is held by a crashed/stuck process.
              Fix: add `timeout=30` to all three and `continue` on failure.

  [DONE] 44. Race condition: state mutated outside lock (`_shared_zproj_state_mixin.py:112-117`)
              — In `z_projection()`, `ckeyelem['image'] = None` and
              `ckeyelem['state'] = 'used'` happen after `lock.release()` at
              line 110. Another thread can read inconsistent state.
              Fix: hold lock while mutating, or re-acquire before mutations.

  [DONE] 45. `signal.signal()` from non-main thread (`_shared_zproj_state_mixin.py:77`)
              — `_zprj_thread()` calls `signal.signal(SIGTERM, ...)` which
              only works in the main thread. Raises `ValueError` if called
              from a worker thread.
              Fix: remove or guard with `threading.current_thread() is threading.main_thread()`.

  [DONE] 46. Stale z-projection cache across renders (`fileops/__init__.py`)
              — When `render_configuration_file_cmd` is called twice in the
              same process, the shared state (`s_dict`, `s_list`) from the
              first render persists. The second render finds entries in
              `state='used'` and raises `FrameNotFoundError`, falling back
              to sequential rendering (no cache). Memory from the first
              render's cache is never freed.
              Fix: add `reset_shared_state()` in `fileops/__init__.py` that
              clears `s_dict` and `s_list`, and call it at the start of
              `render_movie()` or `render_configuration_file_cmd()`.
