--- FILE: fileops/scripts (progress reporting) ---

29. [UX] Terminal commands show no progress when used from the CLI

    The progress_callback plumbing (#18, #28) only benefits programmatic
    callers such as ExperimentTrackerGUI. When the same operations run
    from fileops-summary / fileops-config, the user gets no feedback
    beyond log lines, and long scans (e.g. make over a large data tree)
    look hung.

    Fix: install a default callback in the *_cli wrappers that renders
    progress in the terminal — e.g. a rich/typer progress bar, or plain
    "current/total message" lines — instead of dropping the callback.
    A --quiet flag can suppress it for scripted use.

--- FILE: fileops/export/config.py ---

11. [OPT] build_config_list() reads config files twice (lines 295, 322)

    build_config_list parses each config file once to build the DataFrame
    then re-reads the same file again inside the loop to extract movie
    metadata. This doubles I/O for large collections of config files.

    Fix: Reuse the already-parsed ConfigParser object from the first read
    instead of calling _read_cfg_file() a second time.

--- FILE: fileops/image/_shared_zproj_state_mixin.py ---

12. [BUG] lock.acquire() without timeout (lines 195, 204, 249)

    Three bare acquire() calls in _zproject() can hang forever if the
    lock is held by a crashed or stuck process.

    Fix: add timeout=30 to all three calls and continue on failure.

14. [OPT] Plugin naming convention is fragile and undocumented (export/config.py)

    FileOps matches config types to readers by string-concatenating
    _header_reader (export/config.py:113). A misnamed plugin silently
    does nothing. Should be an explicit mapping or registry.

    self.all_series = self.positions  # FIXME: the series property should be removed from the whole data-structure

    Flagged in-code with FIXME. In this reader all_series is just an alias
    of positions to satisfy the interface, while other readers populate it

--- FILE: fileops/loaders/tiff_loader.py ---

27. [BUG] load_tiff() hardcodes z-step calibration instead of converting to
     micrometers (line 59)

    um_per_z=1,  # TODO: pass to um

    Flagged in-code with TODO. The z-step is hardcoded to 1 um; the ImageJ
    metadata 'spacing' entry (written by Fiji when the stack is calibrated,
    available in the metadata dict read at line 29) is ignored. Any
    z-dependent output (volumetric export, physical scale reporting) gets
    a wrong physical scale for these files unless the true step happens to
    be exactly 1 um.

    Fix: read 'spacing' from the ImageJ metadata, convert it to micrometers
    according to the resolution unit, and fall back to 1 only when absent.

--- FILE: fileops/scripts (GUI-facing public API) ---

33. [OPT] Composite step sequences live on one side or the other, not both

    make_summary_and_sync() reproduces the exact step sequence of the GUI's
    "Generate summary" button (make + update_from_cfg_folder + restore,
    with progress callbacks threaded through). The GUI's generate/update
    flows (generate_config_flow, update_summary_and_configs) are the same
    pattern. If a step sequence is exposed both as a FileOps function/CLI
    command and copied in the GUI, adding a step must be mirrored in both
    callers.

    Decision (2026-09-04): each step sequence lives on exactly one side.
    make_summary_and_sync() stays in FileOps (it encapsulates the
    association-preservation logic and ships a make-and-sync terminal
    command); generate_config_flow() and update_summary_and_configs() are
    pure two-call sequences with no extra logic, so they live only in the
    GUI (src/path_utils/_config.py) and no generate-config / update-all
    CLI commands are added.

    Fix: keep future step sequences on one side only. If a sequence is
    worth a FileOps facade, give it a CLI wrapper mirroring
    make_and_sync_cli and forward a default terminal progress callback
    (see #29) so CLI and GUI remain behaviourally identical.

    41.  OME-TIFFs exported from bioformats/Fiji (e.g. the maximally

           fileops/image/_tifffile_imagej_metadata.py (rebuilt after the
           counts are known), _image_file_ome.py and
           _image_file_bioio_ome.py now pad with the same _pad_width()
           logic as plane_at(); the metadata cache-hit path in
           fileops/mixins/tiff_metadata_mixin.py re-pads the keys it
           restores from the on-disk JSON cache.
         — (c) HistogramMatchProcessor crashed with a cryptic
           AttributeError when the requested reference_frame is out of
           range (mdi was None); it now raises a clear
           FrameNotFoundError telling the user to fix
           'reference_frame'/'frames'.

           reported sizes) on top of the OME-derived counts (181 t x 2 c)
           built by OMEImageFile._load_imageseries. TiffMetadataMixinBase.
           _init_metadata() now performs its cache load/build only on the
           first invocation, so the OME metadata stays authoritative.
Deleting the on-disk metadata cache was never enough — the
            stale values were rewritten by the first init pass.
    41c.  follow-ups for the same OME file family:
          — (e) The user re-exported the file as a PLAIN ImageJ hyperstack

  fileops/export/config_sections.py (config parsing)
    39.  Config parsing ate channel colors written as hex codes.
         read_config()/read_data_section()/update_overrides_from_channel_sections()
         and friends parsed config files with
         inline_comment_prefixes=('#', ';') (added in the defaults-list

         or `[roi_001]` header instead of an .roi file. read_data_section()
         now resolves the value as an existing file first, else looks up
         ROI sections by id or header (case-insensitive) and parses the
         `geometry` into an ImagejRoi, else raises a FileNotFoundError

         fileops/export/_roi.py handles `Square(x, y, side)` and
         `Rectangle(x, y, width, height)` (centered); the ROI header reader
         plugin was refactored to reuse it. Regression tests in
         test/test_config_data_section_roi.py.
